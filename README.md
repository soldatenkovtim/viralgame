# MARKET TRIALS

Браузерный прототип игровой платформы для алготрейдинговой компании.

Три коротких рыночных испытания → персональный профиль поведения в сессии → сравнение с другим трейдером.

Это не образовательная викторина, не казино и не симулятор брокерского терминала. Результат описывает только решения внутри игровой сессии и **не является профессиональной оценкой**.

Весь пользовательский интерфейс на русском языке.

## Запуск

```bash
npm install
npm run dev
```

Откроется `http://localhost:5173`.

Другие команды:

```bash
npm run build      # TypeScript + production-сборка
npm run preview    # просмотр production-сборки
npm test           # scoring-тесты (Vitest)
npm run typecheck  # проверка типов
```

Стандартная и продвинутая серии хранят прогресс в `localStorage` через Zustand persist (`market-trials-v1`). Дуэли используют общий Node.js сервер и SQLite; при `npm run dev` API запускается вместе с Vite. Нужен Node.js 24 или новее.

## Как играть

1. Главная → **Начать испытания**
2. **Слепой рынок** — выбрать 2 из 5 блоков информации, принять 3 решения по ходу графика
3. **Маркет-мейкер** — 60 секунд котировать bid/ask против скрытого бота
4. **Рыночный шок** — позиция уже открыта, 3 фазы с таймером 20 секунд
5. **Профиль** — архетип, пять характеристик, карточка 1200×630
6. **Рейтинг** — тестовая таблица, игрок вставляется по лучшему score
7. После каждого испытания можно **отправить этот рынок другому трейдеру**

Полное прохождение: примерно 8–12 минут.

Debug-режим: добавьте `?debug=1` к любому адресу. В панели можно сбросить прогресс, открыть любое испытание, выбрать сценарий / тип бота, выключить таймер, сразу собрать финальный профиль.

## Где менять контент

### Сценарии

| Испытание | Файл | Идентификаторы |
|---|---|---|
| Слепой рынок | `src/data/blindMarketScenarios.ts` | `blind_01`, `blind_02`, `blind_03` |
| Маркет-мейкер | `src/data/marketMakerScenarios.ts` | `mm_noise`, `mm_informed`, `mm_momentum` |
| Рыночный шок | `src/data/blackSwanScenarios.ts` | `swan_energy`, `swan_liquidity`, `swan_currency` |

Свечи и траектория fair value считаются из `seed`. Shared-ссылка передаёт тот же `scenarioId` + `seed`, поэтому второй игрок видит тот же рынок.

Тексты раскрытия («это был энергетический шок»), блоки информации и crowd-статистика тоже живут в этих файлах.

### Scoring

| Что считается | Файл |
|---|---|
| PnL и score Слепого рынка | `src/games/blind-market/scoring.ts` |
| Сделки ботов маркет-мейкера | `src/games/market-maker/bots.ts` |
| Движок котировок | `src/games/market-maker/engine.ts` |
| Score маркет-мейкера | `src/games/market-maker/scoring.ts` |
| PnL и score рыночного шока | `src/games/black-swan/scoring.ts` |
| Trading Profile, архетипы, текст | `src/lib/profile.ts` |
| «Неожиданные факты» | `src/lib/achievements.ts` |
| Игровой score рейтинга | `computeOverallScore` в `src/lib/profile.ts` |

Характеристики профиля приводятся к диапазону 20–95. Score рейтинга — отдельная величина 0–10 000 и не совпадает с профилем.

### Тексты интерфейса

- Главная и карточки испытаний: `src/pages/HomePage.tsx`, `src/components/ui/ChallengeCard.tsx`
- Результаты: `src/games/*/…Result.tsx`
- Профиль и карточка: `src/pages/ProfilePage.tsx`, `src/components/share/ShareCard.tsx`
- Рейтинг (ники и генерация): `src/data/leaderboard.ts`

## Общие дуэльные комнаты

1. Выбрать «Дуэль» → испытание → «Создать дуэль».
2. Создатель получает комнату `/duel/room/:id`, приглашение для друга и кнопку «Начать своё прохождение».
3. Друг открывает приглашение на своём устройстве, занимает второе место и начинает независимо. Играть можно одновременно или в разное время.
4. Сервер выбирает общий стандартный сценарий и seed из `server/catalog.ts`. Оба начинают новое прохождение. Текущие стандартные результаты в комнату не переносятся.
5. До завершения обоих API отдаёт только статусы. После завершения оба участника получают сравнение; посторонние не получают результаты.
6. «Твои дуэли» на `/play` позволяет вернуться к комнате. Место сохраняется в текущем браузере, без регистрации. Очистка данных браузера теряет доступ к этому месту. Незавершённая попытка после перезагрузки начинается заново на том же рынке; завершённая сохраняется на сервере.
7. При сбое отправки результат остаётся локально: вернуться в комнату и нажать «Отправить результат».

Вызовы с экрана результата и повторные вызовы тоже создают новую комнату. Старые ссылки `?data=…` сохранены только для совместимости: они по-прежнему сравнивают с записанным результатом, общей комнаты у них нет. Для совместной игры нужно новое приглашение.

### Тест в одной Wi-Fi сети

`npm run dev` слушает сетевые интерфейсы на порту 5173. При создании комнаты через localhost поле приглашения автоматически использует локальный IPv4-адрес. Друг должен открыть именно эту ссылку, а не localhost. Оба устройства должны находиться в общей сети, сервер должен оставаться запущенным. IP может измениться после переключения сети. Если в системе несколько интерфейсов, выбирается физический `en*`/`eth*`/`wlan*` перед VPN; адрес можно явно задать через `DUEL_LAN_ORIGIN` при запуске.

### Запуск в интернете

```bash
npm ci
npm run build
DUEL_DB_PATH=/var/lib/market-trials/duels.sqlite PORT=5173 npm start
```

`npm start` запускает `server/start.ts`, который обслуживает API и `dist` на одном origin (SPA fallback включён). Нужны Node.js 24+, один постоянно работающий процесс и постоянный диск для SQLite. Разместить за HTTPS reverse proxy с сохранением заголовка Host, настроить домен и резервное копирование SQLite. Переменные: `HOST` (по умолчанию `0.0.0.0`), `PORT` (5173), `DUEL_DB_PATH` (`.data/duels.sqlite`). Для нескольких серверных экземпляров потребуется транзакционное общее хранилище вместо локального SQLite. Статический хостинг без API не подходит.

Публикация в интернете не выполнялась. Прототип принимает рассчитанные клиентом результаты; сервер проверяет формат и принадлежность комнате, но не обеспечивает защиту от подделки очков. Для соревновательного рейтинга нужна серверная проверка игровых действий.

### Совместимость и проверки

- Advanced открывается после четырёх стандартных испытаний. Его результаты и рекорды отдельные. Дуэли доступны без предварительного стандартного прохождения и не изменяют основной Trading Profile.
- Сценарии исполняются независимо. Общими являются рынок и seed, а не книга заявок или ликвидность.
- Данные комнат хранятся в `.data/duels.sqlite` (исключён из git); ключи места — в `market-trials-room-seats-v1` на устройстве участника.
- `npm test` проверяет общие сценарии, скрытие результатов, два независимых прохождения, исключение третьего игрока, повторные запросы, валидацию и сохранность после перезапуска.
- Остальные проверки: `npm run typecheck`, `npm run build`, `npm run lint`.
